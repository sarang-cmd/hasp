The problem

Your keys are scattered across five tools.

A note in Keep. A text file on the desktop. Three browser tabs you reopened from history. A codes app on the phone that no longer matches the one on the laptop.

Hasp puts them in one list you can search, label by environment, and open with a single password.

Nightshift, the default surface. Drawn from the real tokens and typefaces.

What it does

Four things, and it does them properly.

Stores keys
Each item is sealed under its own key, bound to its position, so a ciphertext moved to another row fails to open instead of opening as something else.
Generates codes
RFC 6238 one-time codes with a depletion bar, checked against the RFC's own test vectors.
Tracks backup codes
Code sets keep an unused count. There is no copy-all button, because copying a set is how sets end up in a chat log.
Imports your exports
Google Keep JSON and HTML, CSV, otpauth URIs, and the JSON dialects of six authenticator apps. Every field carries a confidence score, and anything uncertain goes to review.

Local first

Nothing leaves the machine.

There is no server to trust. The vault is one encrypted file. The interface is served by the same process that holds the key, and the process makes no outbound request at runtime.

Sync is off until you turn it on, and it is a file on your own machine rather than a service. When it is on, two devices exchange the same ciphertext the vault already holds. Nothing is readable in transit, because nothing readable is ever sent.

There is still no account recovery and no sharing. Both need a party that can hold something for you, and this product has none.

Sample build. Every item in the demonstration is invented. The sample master password is printed on the unlock screen on purpose. Do not put a real secret into this build.
