Security

Tested, not audited.

That is the honest summary. This page states the guarantees, the gaps, and the threat model, and it names the test that fails if a guarantee is removed.

What is guaranteed

The password is never stored
It derives a key with scrypt, and that key unwraps a random vault key. Only the wrapped key reaches disk.
Ciphertext is bound to its position
Associated data covers the vault id, the item id and the version. A moved or rolled-back ciphertext fails to open.
Wrong password is indistinguishable from a corrupt vault
Both fail at the unwrap with the same error.
Nothing is written in plaintext
The vault file is checked after every write for values that should only exist encrypted.
Guessing is bounded
Three free attempts, then a doubling wait to a two minute ceiling. A correct password is refused while the wait runs, so the throttle is not an oracle.
The browser is constrained
HttpOnly, SameSite=Strict cookies. Cross-origin posts refused. CSP default-src self, with one inline script allowed by hash.

What is not

No independent review
The cryptography has not been audited. Tests find the bugs someone thought to test for.
Not XChaCha20
The cipher is ChaCha20-Poly1305 with a 12 byte nonce, not the XChaCha20-Poly1305 the plan specifies.
Server-side cryptography
Derivation and sealing happen in the Node process, and plaintext crosses the loopback interface. This is not a client-side encryption architecture.
No transport security
Hasp serves plain HTTP. Put it behind TLS or bind it to loopback.
No defence against a compromised host
If something can read the process memory, it can read the vault key.
No key rotation
Changing the master password is not implemented.

Threat model

In scope. Someone with the vault file but not the password. Someone sending requests to a running instance. A stolen device left unlocked, where the idle lock is a speed bump rather than a wall.

Out of scope. Malware on the machine, a compromised browser, a keylogger, and the operator. A local web app cannot solve those, and claiming otherwise would be the dishonest part of a security page.

Report a vulnerability privately. Do not open a public issue.
